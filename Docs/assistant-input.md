## Observed problem and change

With the native iPad keyboard open in landscape, the old 600-point square scaled its Send button down to 24.16 points. The rotation test preserved the draft and did not send it, but its recorded geometry exposed the usability problem. The assistant now uses the available width and height without scaling its controls; Send measures 48 × 48 points in both tested orientations on iPad and iPhone. Other screens retain their existing square layout.

The response document scrolls independently above a pinned composer. More space at the top keeps the tested app-edge Control Center drag away from the screen edge in compact landscape. Rectangular gesture arbitration uses actual width and height, retaining square-face thresholds. This does not reconstruct Apple's recognizers or claim exclusive ownership of system gestures.

The labelled Assistant entry also accepts **Cmd-Shift-S** within the app. Entry/re-entry focuses the draft. A visible **Dismiss keyboard** action closes typing without sending or deleting it. Navigation preserves the draft; background clears it. Submission is guarded to the active, uncovered assistant route. Text-input newline submission is explicitly Send-labelled. A phone's very compact landscape layout can require keyboard dismissal before document/navigation controls are reachable.

## Failed candidates are retained, not accepted

The receipt preserves all nine checkpoints: 57 executions overall, including 22 failed executions in unpublished candidates. These are not relabelled delivery successes. Failures include the old square-only image helper, test rotation/clear/navigation assumptions, raw Escape/Return injection, and an unsuccessful native field-adapter experiment. The native adapter is **not delivered**. The source/compiled archives preserve its failures separately. Initial x86_64/arm64 package mismatch and tvOS shortcut-unavailability builds were also retained; explicit target architecture and platform guards resolved the build boundaries.

Raw Escape and raw Return key injections did not produce accepted results. Whether the unresolved boundary is the app, UIKit/SwiftUI or the tested input transport is not established; no physical-keyboard fix is claimed. The accepted submission case uses XCTest's text-input newline path, not that raw Return injection. The visible dismissal action is the delivered cancellation path.

Physical VoiceOver, Switch Control, hardware keyboard, real OS Control Center/notification-edge interactions and original gesture/visual equivalence remain open.
