# Native OS motion calibration sources

These exact frozen excerpts preserve the scope of successive diagnostics; they are not interchangeable product acceptance results. [Hashes and original test-source digests](manifest.json).

- **Full root inventory:** read-only Settings navigation/AX data, not HomeView behavior. Per-node queries took roughly70 seconds on phone and240 on pad. The requested120-second test allowance was not an enforced wall cap because the launch configuration had `TestTimeoutsEnabled=false`. The expensive diagnostic is archived outside the normal target.
- **Indexed menu inventory:** pad reached Motion and the actual `REDUCE_MOTION` switch value0/native getter false. Phone failed on a live indexed AX node. The later public snapshot-string capture changes only instrumentation, not the navigation/switch/native-state assertions. No OS capability absence or product defect is inferred.
- **First Flow OFF/ON pilot:** real OS state0→1→0, moving/still regions and restored original value observed. It has no OFF-again movement requirement and is not the final stronger matrix.
- **First OFF/ON/OFF matrix:** visual/switch conditions passed, but its `same_app_lifetime=true` field was literal test intent, not a PID measurement. These remain valid visual/state observations, not current no-restart acceptance. There is also no evidence that a restart actually happened.

The stronger normal-target test measures the PID from the root attributes of public `XCUIApplication.debugDescription` at every foreground/surface-qualified phase, fails on an unrecognized format and requires equality. No private `processID`/KVC is used. Original preference values and restoration are verified separately from process continuity, pixels, physical-device behavior and power.

Full Settings screenshots, AX strings, original failure logs and compiled bundles remain private. Only own source excerpts, normalized receipts and own HomeView viewport images are candidates for publication.
